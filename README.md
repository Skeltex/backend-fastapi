# backend-fastapi

REST API блога на FastAPI: пользователи, категории, местоположения, публикации и комментарии. Проект перенесен с Django, данные хранятся в SQLite.

## Локальный запуск

Нужны Python 3.14 и [uv](https://docs.astral.sh/uv/).

1. Скопируйте `.env.example` в `.env` и задайте `SECRET_KEY`. Для `HS256` ключ должен быть не короче 32 байт, для `HS384` не короче 48, для `HS512` не короче 64. Сгенерировать ключ можно так:

   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(64))"
   ```

2. Установите зависимости и примените миграции:

   ```bash
   uv sync
   uv run alembic upgrade head
   ```

3. Запустите сервер:

   ```bash
   uv run fastapi dev main.py
   ```

API доступно по адресу http://localhost:8000/api/v1, документация по адресу http://localhost:8000/docs.

Если папку проекта переносили или переименовывали, пересоздайте окружение командой `uv venv --clear && uv sync`: скрипты в `.venv` хранят абсолютные пути.

## Docker

```bash
docker compose up
```

Перед запуском нужен файл `.env` из шага 1. Образ пересобирается при каждом `docker compose up`, поэтому контейнер всегда запускается с текущим кодом. Миграции применяются при старте контейнера, состояние проверяется через `GET /api/v1/health`. База лежит в `data/`, логи в `logs/`. Приложение в контейнере работает от пользователя с UID 1000, поэтому на Linux эти каталоги нужно создать заранее от своего пользователя.

## Миграции

Миграции рассчитаны на SQLite и PostgreSQL. Генерация SQL без подключения к базе (`alembic upgrade --sql`) для SQLite не поддерживается: изменение таблиц в SQLite требует чтения их текущей структуры.

Миграция `c41dc2ca3e14` приводит email к нижнему регистру и делает имена пользователей и email уникальными без учета регистра. Если в базе уже есть такие дубликаты, миграция остановится и выведет их список.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `SECRET_KEY` | нет, обязательна | Ключ подписи JWT |
| `ALGORITHM` | `HS256` | Алгоритм подписи: `HS256`, `HS384` или `HS512` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `30` | Время жизни токена в минутах |
| `DATABASE_URL` | `data/db.sqlite3` в корне проекта | Строка подключения SQLAlchemy |
| `LOG_FILE` | `logs/app.log` в корне проекта | Файл логов |
| `CORS_ORIGINS` | `*` | Разрешенные источники для CORS через запятую или JSON-списком |
| `AUTH_FAILURES_LIMIT` | `10` | Сколько неудачных попыток входа или конфликтов при регистрации допускается с одного адреса |
| `AUTH_FAILURES_WINDOW_SECONDS` | `300` | Окно в секундах, за которое считаются неудачные попытки |
| `MAX_REQUEST_BODY_BYTES` | `1048576` | Максимальный размер тела запроса в байтах |

## Доступ

- Регистрация (`POST /api/v1/users/`) и чтение опубликованных данных доступны без токена.
- Токен выдает `POST /api/v1/auth/token`, свой профиль доступен по `/api/v1/users/me`.
- Для смены своего пароля в `PATCH /api/v1/users/me` нужно передать `current_password`. После смены пароля все выданные ранее токены перестают действовать.
- После серии неудачных попыток входа или регистрации API отвечает `429` с заголовком `Retry-After`.
- Публикации и комментарии изменяет и удаляет автор или администратор.
- Категории, местоположения и чужие учетные записи изменяет только администратор. Первого администратора назначают в базе: `UPDATE auth_user SET is_superuser = 1 WHERE username = '...';`. Последнего администратора нельзя отключить, удалить или лишить прав.
- Неопубликованные категории и местоположения видит только администратор. Неопубликованные и отложенные публикации, а также публикации из скрытых категорий видят их автор и администратор. Публикации идут от новых к старым по дате публикации.
- Список пользователей без прав администратора содержит только активные учетные записи и публичные поля.
- Пользователи, перенесенные из Django, входят со старым паролем. При первом входе хэш пароля переводится на bcrypt.
